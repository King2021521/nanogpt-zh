# 标点符号抑制优化说明

## 问题描述

在交互式生成中发现，某些输入会导致模型生成大量连续的标点符号，例如：

```
输入: 会当凌绝顶
输出: ，。，。，。，。，。，。。。。。。。，。。。。。，。。。。。。与。。。。。。。。。。。。。。。。。。
```

**问题原因**：
1. 输入较短时，模型缺乏足够的上下文
2. 模型在训练时学习到了标点符号的高频模式
3. 一旦开始生成标点，容易陷入标点循环

## 解决方案

### 核心改进：连续标点符号检测与抑制

在 `models/gpt.py` 的 `generate()` 方法中添加了智能标点抑制机制：

```python
# 记录最近生成的token，用于检测连续标点符号
recent_tokens = []

for step in range(max_new_tokens):
    # ... 前向传播 ...
    
    # 抑制连续标点符号：如果最近生成的2-3个token都是标点，大幅降低标点概率
    if suppress_punct_tokens is not None and len(recent_tokens) >= 2:
        # 检查最近2个token是否都是标点
        recent_punct_count = sum(1 for t in recent_tokens[-2:] if t in suppress_punct_tokens)
        if recent_punct_count >= 2:
            # 如果连续2个都是标点，大幅降低所有标点的概率
            for punct_id in suppress_punct_tokens:
                logits[:, punct_id] = logits[:, punct_id] - 15.0
        elif recent_punct_count >= 1:
            # 如果最近有1个标点，适度降低标点概率
            for punct_id in suppress_punct_tokens:
                logits[:, punct_id] = logits[:, punct_id] - 5.0
    
    # ... 采样逻辑 ...
    
    # 记录最近生成的token（用于下一轮检测）
    next_token_id = next_token.item()
    recent_tokens.append(next_token_id)
    if len(recent_tokens) > 5:  # 只保留最近5个token
        recent_tokens.pop(0)
```

### 工作原理

1. **实时监控**：记录最近生成的5个token
2. **梯度惩罚**：
   - 如果最近2个token都是标点：标点logit减少15.0（大幅降低概率）
   - 如果最近1个token是标点：标点logit减少5.0（适度降低概率）
3. **动态调整**：每生成一个token，都会更新监控窗口

### 支持的标点符号

```python
punct_tokens = ['，', '。', '、', '；', '：', '？', '！', ',', '.', '·', '…']
```

涵盖了中英文常见标点符号。

## 局限性

### 仍然存在的问题

1. **极短输入**：对于"会当凌绝顶"这样的极短输入，效果有限
2. **模型本质**：根本问题是模型困惑度高（49.77），需要更多训练
3. **无法完全消除**：只能降低标点占比，无法完全避免

### 为什么某些情况效果有限？

1. **上下文不足**：输入太短（3-5个字），模型缺乏足够信息
2. **模型容量**：18M参数相对较小，表达能力有限
3. **训练不足**：80,000步训练，困惑度49.77仍然偏高

## 技术细节

### 参数说明

- `suppress_punct_tokens`：标点符号token ID列表
- `recent_tokens`：最近生成的5个token的滑动窗口
- 惩罚力度：
  - 连续2个标点：-15.0 logit（约降低99.9%概率）
  - 连续1个标点：-5.0 logit（约降低99%概率）

### 为什么不完全禁止标点？

1. **诗词需要标点**：诗词中标点是必要的，不能完全禁止
2. **平衡策略**：只抑制"连续"标点，允许正常的标点使用
3. **动态调整**：根据最近生成的内容动态调整抑制力度
