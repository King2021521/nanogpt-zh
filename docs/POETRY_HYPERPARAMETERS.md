## 🎯 训练策略

### 训练计划

```
数据集规模: 367,896 条训练样本
批次大小: 64
每轮步数: 5,748 步
训练轮数: 20 轮
总训练步数: 100,000 步（约17.4轮）
```

### 时间估算

| 设备 | 预计训练时间 | 说明 |
|------|------------|------|
| **NVIDIA RTX 3090** | ~13-15 小时 | 推荐配置 |
| **NVIDIA RTX 3080** | ~15-18 小时 | 良好性能 |
| **NVIDIA RTX 3060** | ~20-25 小时 | 可接受 |
| **CPU (16核)** | ~140+ 小时 | 不推荐 |

### 检查点策略

- **保存间隔**: 每 2,000 步保存一次
- **评估间隔**: 每 1,000 步评估一次
- **预计保存**: 50 个检查点
- **磁盘空间**: 约 5-10 GB

## 🔧 超参数调整建议

### 1. 显存不足时

如果遇到 CUDA Out of Memory 错误：

```python
# 方案1: 减小批次大小
batch_size = 32  # 从64减到32

# 方案2: 减小模型维度
d_model = 256    # 从384减到256
d_ff = 1024      # 从1536减到1024

# 方案3: 减小序列长度
max_seq_len = 96  # 从128减到96
```

### 2. 训练速度慢时

```python
# 增大批次大小（如果显存允许）
batch_size = 128

# 减少评估频率
eval_interval = 2000

# 使用混合精度训练（需要修改Trainer）
# 可以提速2-3倍
```

### 3. 过拟合时

```python
# 增加Dropout
dropout = 0.2

# 增加权重衰减
weight_decay = 0.05

# 减少训练轮数
max_epochs = 10
```

### 4. 欠拟合时

```python
# 增大模型容量
d_model = 512
n_layers = 10

# 增加训练步数
max_steps = 150000

# 提高学习率
learning_rate = 8e-4
```

## 📊 学习率调度策略

### Warmup + Cosine Decay

```
步数 0-2000:      线性预热 (0 → 5e-4)
步数 2000-100000: 余弦衰减 (5e-4 → 5e-5)
```

### 为什么使用这个策略？

1. **预热阶段**: 避免训练初期梯度过大导致不稳定
2. **余弦衰减**: 后期降低学习率以精细调优
3. **最终学习率**: 保持小的学习率以避免遗忘

## 🎨 生成参数调优

### Temperature（温度）

| 值 | 效果 | 适用场景 |
|----|------|---------|
| 0.5 | 非常保守，重复性高 | 生成格律严谨的诗词 |
| **0.8** | 平衡创造性和连贯性 | **推荐默认值** |
| 1.0 | 标准采样 | 增加多样性 |
| 1.2 | 更有创造性，可能不连贯 | 实验性创作 |

### Top-K 和 Top-P

```python
# 保守策略（高质量）
top_k = 20
top_p = 0.75

# 平衡策略（推荐）
top_k = 40
top_p = 0.85

# 创新策略（多样性）
top_k = 60
top_p = 0.95
```

## 📝 训练监控指标

### 关键指标

1. **训练损失 (train_loss)**
   - 应该持续下降
   - 目标: < 2.0

2. **验证损失 (val_loss)**
   - 应该跟随训练损失下降
   - 如果上升，说明过拟合

3. **困惑度 (perplexity)**
   - perplexity = exp(loss)
   - 越低越好
   - 目标: < 10

4. **学习率 (learning_rate)**
   - 检查预热和衰减是否正常

### 健康的训练曲线

```
Epoch 1:  train_loss=4.5, val_loss=4.3
Epoch 5:  train_loss=3.2, val_loss=3.1
Epoch 10: train_loss=2.5, val_loss=2.6
Epoch 15: train_loss=2.0, val_loss=2.2
Epoch 20: train_loss=1.8, val_loss=2.1
```

## 💡 最佳实践

### ✅ 推荐做法

1. **使用GPU训练** - 至少RTX 3060或更好
2. **定期检查验证损失** - 避免过拟合
3. **保存多个检查点** - 可以回退到更好的版本
4. **使用TensorBoard监控** - 实时查看训练曲线
5. **测试不同的生成参数** - 找到最佳的temperature和top_k

### ❌ 避免的错误

1. ❌ 在CPU上训练大模型 - 太慢了
2. ❌ 批次大小太小 - 训练不稳定
3. ❌ 学习率太高 - 可能不收敛
4. ❌ 不做验证 - 无法发现过拟合
5. ❌ 只保存最后一个检查点 - 可能错过最佳模型

## 🔍 常见问题

### Q1: 为什么诗词配置的参数量增加了3倍？

**A**: 诗词生成需要学习复杂的韵律、格律和语义关系。更大的模型容量（d_model=384, n_layers=8）可以更好地捕捉这些特征。

### Q2: 我的GPU显存只有4GB，能训练吗？

**A**: 可以，但需要调整参数：
- batch_size = 16
- d_model = 256
- max_seq_len = 96

### Q3: 训练多少步可以看到效果？

**A**: 通常在5,000-10,000步后就能生成基本连贯的诗词，但要达到高质量需要完整训练。

### Q4: 如何判断模型训练好了？

**A**: 观察以下指标：
1. 验证损失不再下降
2. 生成的诗词连贯且有意义
3. 困惑度 < 10

### Q5: 可以在训练中途修改超参数吗？

**A**: 可以，但建议只修改：
- learning_rate（可以手动降低）
- temperature（生成参数）
- save_interval / eval_interval

不建议修改模型架构参数（d_model, n_layers等）。
