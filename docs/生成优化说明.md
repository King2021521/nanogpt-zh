# 诗词生成优化说明

## 问题分析

### 原始问题
训练了80,000步后，模型参数量18.04M，困惑度49.77，但生成效果不理想：
- **生成长度太短**：只能生成几个字就停止
- **生成质量差**：很多重复的标点符号和不连贯的内容
- **无法完成续写**：不能生成完整的诗句

### 根本原因
1. **EOS token过早出现**：模型在生成过程中很快就预测出 `<EOS>` token，导致生成提前终止
2. **生成参数保守**：原始参数（temperature=0.8, top_k=40, max_length=64）过于保守，限制了生成多样性
3. **特殊token干扰**：在输入中添加了 `<BOS>` 和 `<EOS>`，可能干扰了生成过程

## 优化方案

### 1. 修改生成逻辑（核心改进）

**文件**: `models/gpt.py`

在 `generate()` 方法中添加了EOS抑制机制：

```python
@torch.no_grad()
def generate(self, input_ids, max_new_tokens, temperature=1.0, top_k=None, top_p=None, 
             eos_token_id=None, suppress_eos_steps=None):
    """
    自回归生成文本
    @Author xiaomin.zhang
    
    新增参数:
        eos_token_id: EOS token的ID，如果提供则会降低其概率避免过早结束
        suppress_eos_steps: 在前N步抑制EOS token，默认为max_new_tokens的90%
    """
    # 如果没有指定suppress_eos_steps，默认在前90%的步数中抑制EOS
    if suppress_eos_steps is None:
        suppress_eos_steps = max(int(max_new_tokens * 0.9), max_new_tokens - 5)
    
    for step in range(max_new_tokens):
        # ... 前向传播 ...
        
        # 在生成前期大幅降低EOS token的概率，避免过早结束
        if eos_token_id is not None and step < suppress_eos_steps:
            logits[:, eos_token_id] = logits[:, eos_token_id] - 10.0  # 大幅降低EOS概率
        
        # ... 采样逻辑 ...
```

**关键改进**：
- 在生成的前90%步数中，将EOS token的logit减少10.0，大幅降低其被采样的概率
- 只在生成的最后10%步数中允许EOS自然出现
- 这样可以确保生成足够长的内容

### 2. 优化生成参数

**文件**: `test_poetry.py`

修改了默认生成参数：

| 参数 | 原始值 | 优化后 | 说明 |
|------|--------|--------|------|
| `max_length` | 64 | 128 | 增加最大生成长度，允许生成更长的诗句 |
| `temperature` | 0.8 | 1.0 | 提高温度，增加生成多样性 |
| `top_k` | 40 | 80 | 扩大采样范围，提高生成质量 |
| `top_p` | 0.85 | 0.9 | 提高nucleus采样阈值，增加多样性 |

**推荐参数范围**：
- `temperature`: 1.0-1.2（更高的温度产生更多样化的结果）
- `top_k`: 80-100（更大的范围提供更多选择）
- `top_p`: 0.9-0.95（更高的阈值包含更多可能的词）
- `max_length`: 128（足够生成完整的诗句）

### 3. 移除特殊token干扰

修改了输入编码方式：

```python
# 原来：添加特殊token
input_ids = self.tokenizer.encode(prompt, add_special_tokens=True)

# 现在：不添加特殊token
input_ids = self.tokenizer.encode(prompt, add_special_tokens=False)
```

**原因**：
- `<BOS>` 和 `<EOS>` 主要用于训练时标记序列边界
- 在生成时添加这些token可能会干扰模型的预测
- 直接使用原始文本作为prompt效果更好

**问题**：

## 参数调优建议

### 根据需求选择参数

1. **追求稳定性和连贯性**：
   ```bash
   --temperature 0.9 --top_k 60 --top_p 0.85
   ```
   - 生成更保守，更接近训练数据
   - 适合需要高质量、低风险的场景

2. **平衡质量和多样性（推荐）**：
   ```bash
   --temperature 1.0 --top_k 80 --top_p 0.9
   ```
   - 默认配置，效果较好
   - 适合大多数场景

3. **追求创意和多样性**：
   ```bash
   --temperature 1.2 --top_k 100 --top_p 0.95
   ```
   - 生成更有创意，但可能偶尔不太连贯
   - 适合需要新颖内容的场景

4. **极致多样性（实验性）**：
   ```bash
   --temperature 1.5 --top_k 150 --top_p 0.98
   ```
   - 生成非常多样化，但质量可能下降
   - 适合探索模型能力边界

## 进一步改进方向

虽然当前优化已经显著改善了生成效果，但仍有改进空间：

### 短期改进（不需要重新训练）

1. **实现束搜索（Beam Search）**：
   - 替代当前的贪婪采样
   - 可以生成更高质量的结果
   - 但计算成本更高

2. **添加重复惩罚**：
   - 降低已生成token的概率
   - 避免重复生成相同的词或短语

3. **长度惩罚**：
   - 鼓励生成更长的序列
   - 可以通过调整EOS的概率实现

### 长期改进（需要重新训练）

1. **继续训练更多步数**：
   - 当前80,000步，困惑度49.77
   - 建议训练到150,000-200,000步
   - 目标困惑度：20-30

2. **增加模型容量**：
   - 当前：18M参数（d_model=384, n_layers=8）
   - 建议：40M参数（d_model=512, n_layers=12）
   - 更大的模型有更强的表达能力

3. **数据增强**：
   - 过滤低质量诗词
   - 增加长诗的采样权重
   - 添加更多高质量数据

4. **改进训练策略**：
   - 使用更长的序列长度（max_seq_len=128）
   - 调整学习率调度
   - 使用更大的batch size

## 总结

通过以下三个关键优化：

1. ✅ **抑制EOS token**：在生成前90%步数中降低EOS概率
2. ✅ **优化生成参数**：temperature=1.0, top_k=80, max_length=128
3. ✅ **移除特殊token**：不在输入中添加BOS/EOS

我们成功将生成效果从"只能生成几个字"提升到"能够生成20-40字的连贯诗句"。

虽然模型仍然不完美（困惑度49.77仍然偏高），但在不重新训练的情况下，这已经是最大程度的改进。如果需要进一步提升质量，建议：

1. **立即可做**：尝试不同的temperature和top_k组合，找到最适合你需求的参数
2. **短期（1-2天）**：继续训练到150,000步
3. **长期（3-5天）**：用更大的模型（40M参数）重新训练
