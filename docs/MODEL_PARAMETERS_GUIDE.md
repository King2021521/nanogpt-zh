# NanoGPT-ZH 模型参数详解与优化指南

## 📊 当前模型配置

### 基本信息
```python
模型名称: NanoGPT-ZH (Nano GPT for Chinese)
架构类型: Decoder-Only Transformer (GPT风格)
总参数量: 7,292,928 (约7.3M)
训练数据: 571,696条中文文本 (约50M tokens)
数据来源: 中文维基百科
```

### 核心超参数
```python
vocab_size = 10,000      # 词表大小
d_model = 256            # 模型维度（嵌入维度）
n_layers = 6             # Transformer层数
n_heads = 8              # 注意力头数
d_ff = 1,024             # 前馈网络维度
max_seq_len = 256        # 最大序列长度
dropout = 0.1            # Dropout概率
```

---

## 🧮 参数量详细计算

### 1. Token嵌入层（Embedding Layer）

**公式**：
```python
参数量 = vocab_size × d_model
```

**计算**：
```python
= 10,000 × 256
= 2,560,000 参数
= 2.56M
```

**占比**: 35.1% of 总参数

**说明**：
- 将每个token（词）映射为d_model维的向量
- 这是模型的"词典"，存储每个词的语义表示
- **权重共享**：输出层与嵌入层共享权重，节省了2.56M参数

---

### 2. 位置编码（Positional Encoding）

**参数量**: **0** (不计入可训练参数)

**说明**：
- 使用固定的sin/cos函数编码位置信息
- 不参与梯度更新
- 公式：
  ```
  PE(pos, 2i) = sin(pos / 10000^(2i/d_model))
  PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
  ```

---

### 3. Transformer Block（单层）

每个Transformer Block包含三个主要组件：

#### 3.1 多头自注意力（Multi-Head Attention）

**组成**：
- Query投影矩阵 (W_q)
- Key投影矩阵 (W_k)
- Value投影矩阵 (W_v)
- 输出投影矩阵 (W_o)

**计算**：
```python
W_q = d_model × d_model = 256 × 256 = 65,536
W_k = d_model × d_model = 256 × 256 = 65,536
W_v = d_model × d_model = 256 × 256 = 65,536
W_o = d_model × d_model = 256 × 256 = 65,536

总计 = 4 × 65,536 = 262,144 参数
```

**注意力机制核心公式**：
```
Attention(Q, K, V) = softmax(QK^T / √d_k) × V
```
其中 `d_k = d_model / n_heads = 256 / 8 = 32`

#### 3.2 前馈神经网络（Feed-Forward Network）

**结构**：
```python
FFN(x) = GELU(Linear1(x)) → Linear2
```

**计算**：
```python
# 第一层：d_model → d_ff
Linear1_weight = d_model × d_ff = 256 × 1,024 = 262,144
Linear1_bias = d_ff = 1,024

# 第二层：d_ff → d_model
Linear2_weight = d_ff × d_model = 1,024 × 256 = 262,144
Linear2_bias = d_model = 256

总计 = 262,144 + 1,024 + 262,144 + 256 = 525,568 参数
```

**说明**：
- FFN是参数量最大的组件（占单层的66.6%）
- 使用GELU激活函数（而非ReLU）
- d_ff通常是d_model的4倍

#### 3.3 Layer Normalization（2个）

**计算**：
```python
# 每个LayerNorm有gamma(缩放)和beta(偏移)
LN1 = d_model × 2 = 256 × 2 = 512
LN2 = d_model × 2 = 256 × 2 = 512

总计 = 1,024 参数
```

**说明**：
- 用于稳定训练
- 参数量很小，但作用重要

#### 单层Transformer Block总计

```python
单层参数 = Attention + FFN + LayerNorm
        = 262,144 + 525,568 + 1,024
        = 788,736 参数
```

---

### 4. 所有Transformer Blocks（6层）

**计算**：
```python
总参数 = 788,736 × 6
       = 4,732,416 参数
       = 4.73M
```

**占比**: 64.9% of 总参数

---

### 5. 最后的Layer Normalization

**计算**：
```python
ln_f = d_model × 2 = 256 × 2 = 512 参数
```

---

### 6. 输出层（Language Model Head）

**参数量**: **0** (与嵌入层共享权重)

**说明**：
```python
# 权重共享机制
self.lm_head.weight = self.token_embedding.embedding.weight
```

如果不共享，需要额外：
```python
额外参数 = vocab_size × d_model = 10,000 × 256 = 2,560,000
总参数会变成 = 7.3M + 2.56M = 9.85M
```

## 🎛️ 核心参数说明

### 1. vocab_size（词表大小）

**当前值**: 10,000

**作用**：
- 定义模型能识别的不同词汇数量
- 直接影响嵌入层参数量

**影响**：
- 增加：能识别更多词，但参数量线性增长
- 减少：参数量减少，但可能出现更多未知词(UNK)

**推荐范围**：
- 小型模型：5,000 - 15,000
- 中型模型：30,000 - 50,000
- 大型模型：50,000 - 100,000

**参数量影响**：
```python
vocab_size = 5,000  → 嵌入层 1.28M  (总参数 6.01M)
vocab_size = 10,000 → 嵌入层 2.56M  (总参数 7.29M) ✓ 当前
vocab_size = 20,000 → 嵌入层 5.12M  (总参数 9.85M)
vocab_size = 50,000 → 嵌入层 12.8M  (总参数 17.5M)
```

---

### 2. d_model（模型维度）

**当前值**: 256

**作用**：
- 模型的"宽度"，决定表示能力
- 影响所有层的参数量

**影响**：
- 增加：表示能力更强，但参数量**平方级**增长
- 减少：参数量减少，但表达能力下降

**推荐范围**：
- 小型模型：128 - 512
- 中型模型：512 - 1024
- 大型模型：1024 - 4096

**参数量影响**（最显著）：
```python
d_model = 128  → 总参数 2.0M   (减少73%)
d_model = 256  → 总参数 7.3M   ✓ 当前
d_model = 512  → 总参数 28.3M  (增加288%)
d_model = 1024 → 总参数 111M   (增加1421%)
```

**计算公式**：
```
参数量 ≈ O(d_model²) × n_layers
```

---

### 3. n_layers（层数）

**当前值**: 6

**作用**：
- 模型的"深度"，决定抽象能力
- 每增加一层，增加约788K参数

**影响**：
- 增加：能学习更复杂的模式，但训练更慢
- 减少：训练更快，但表达能力有限

**推荐范围**：
- 小型模型：4 - 12层
- 中型模型：12 - 24层
- 大型模型：24 - 96层

**参数量影响**（线性）：
```python
n_layers = 4  → 总参数 5.7M   (减少22%)
n_layers = 6  → 总参数 7.3M   ✓ 当前
n_layers = 12 → 总参数 12.0M  (增加64%)
n_layers = 24 → 总参数 21.5M  (增加195%)
```

---

### 4. n_heads（注意力头数）

**当前值**: 8

**作用**：
- 多头注意力的头数
- 允许模型关注不同的特征子空间

**约束**：
```python
d_model 必须能被 n_heads 整除
d_k = d_model / n_heads  # 每个头的维度
```

**影响**：
- **不影响参数量**（总维度不变）
- 影响计算效率和表达能力

**推荐范围**：
```python
d_model = 256  → n_heads = 4, 8, 16
d_model = 512  → n_heads = 8, 16
d_model = 1024 → n_heads = 16, 32
```

**当前配置**：
```python
n_heads = 8
d_k = 256 / 8 = 32  # 每个头的维度
```

---

### 5. d_ff（前馈网络维度）

**当前值**: 1,024

**作用**：
- FFN中间层的维度
- 通常是d_model的4倍

**影响**：
- 增加：更强的非线性变换能力
- 是单层中参数量最大的部分

**推荐范围**：
```python
d_ff = d_model × 4  # 标准配置
d_ff = d_model × 2  # 轻量级
d_ff = d_model × 8  # 大容量
```

**参数量影响**：
```python
d_ff = 512  → FFN参数 263K  (总参数 5.7M)
d_ff = 1024 → FFN参数 526K  (总参数 7.3M) ✓ 当前
d_ff = 2048 → FFN参数 1.05M (总参数 10.4M)
```

---

### 6. max_seq_len（最大序列长度）

**当前值**: 256

**作用**：
- 模型能处理的最大token数
- 影响位置编码和注意力计算

**影响**：
- **不直接影响参数量**
- 影响显存占用和计算复杂度

**计算复杂度**：
```python
注意力计算复杂度 = O(seq_len²)
```

**推荐范围**：
- 短文本：128 - 512
- 中等文本：512 - 2048
- 长文本：2048 - 8192

**显存占用**：
```python
max_seq_len = 128  → 显存占用 ~1.5GB
max_seq_len = 256  → 显存占用 ~2.0GB  ✓ 当前
max_seq_len = 512  → 显存占用 ~4.0GB
max_seq_len = 1024 → 显存占用 ~8.0GB
```

---

### 7. dropout（Dropout概率）

**当前值**: 0.1

**作用**：
- 正则化技术，防止过拟合
- 训练时随机丢弃神经元

**影响**：
- **不影响参数量**
- 影响训练稳定性和泛化能力

**推荐范围**：
```python
小数据集：0.1 - 0.3  # 更强的正则化
中数据集：0.1 - 0.2  ✓ 当前
大数据集：0.0 - 0.1  # 较弱的正则化
```

### 方向三：优化训练效率

#### 3.1 混合精度训练⭐⭐⭐⭐⭐

**实现**：
```python
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()

with autocast():
    logits, loss = model(input_ids, targets)
    
scaler.scale(loss).backward()
scaler.step(optimizer)
scaler.update()
```

**效果**：
- 训练速度提升2-3倍
- 显存占用减少50%
- 精度损失可忽略

#### 3.2 梯度累积⭐⭐⭐⭐

**实现**：
```python
accumulation_steps = 4

for i, (input_ids, targets) in enumerate(dataloader):
    logits, loss = model(input_ids, targets)
    loss = loss / accumulation_steps
    loss.backward()
    
    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

**效果**：
- 模拟更大的batch size
- 减少显存需求
- 训练更稳定

## 💡 实用建议

### 1. 参数量与数据量匹配

**经验法则**：
```
训练数据(tokens) ≈ 参数量 × 20

当前: 7.3M参数 × 20 = 146M tokens
实际: 50M tokens (不足)

推荐: 增加到150-200M tokens
```

### 2. 显存与参数量关系

**估算公式**：
```
显存需求(GB) ≈ 参数量(M) × 4 / 1000 × (1 + 梯度 + 优化器)
             ≈ 参数量(M) × 16 / 1000

当前: 7.3M × 16 / 1000 ≈ 0.12GB (理论)
实际: 约2GB (包含激活值和batch数据)
```

### 3. 训练时间估算

**粗略估算**：
```
训练时间 ∝ 参数量 × 数据量 / GPU算力

当前(CPU): 数天
当前(单A100): 数小时
50M模型(单A100): 2-3天
```
