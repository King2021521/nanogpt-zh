## 二、超参调整建议

### 2.1 学习率与调度（优先）

- **现象**：训练 loss 在 2.7–2.8、困惑度 15–16 趋稳，收敛偏慢或欠拟合。
- **建议**：
  - **提高峰值学习率**：在现有 `learning_rate = 2e-4` 基础上，可尝试 **3e-4** 或 **5e-4**，观察前 5 万步 loss 是否更快下降；若震荡再略降。
  - **延长预热**：将 `warmup_steps` 从 2000 提到 **4000 或 5000**，使大 batch 下前期更稳定。
  - **放缓衰减**：若使用 `max_steps`，可增大 `max_steps`（如 **400000**），或修改调度公式，使余弦衰减在更晚的步数才接近 0，避免过早“学不动”。
  - **固定步数后保持小学习率**：例如在 0.9 * max_steps 之后不再衰减，保持 1e-5 级别的小 lr 再跑一段时间。

### 2.2 训练步数与轮数

- **当前**：`max_steps = 300000`，`max_epochs = 30`，实际总步数取两者约束的较小值。
- **建议**：
  - 若验证 loss 仍在缓慢下降：将 `max_steps` 提高到 **400000–500000**，或适当提高 `max_epochs`，确保有足够步数收敛。
  - 每 5000 步或每 1 万步在验证集上算一次 loss/困惑度，保存验证最优检查点，避免只按步数停。

### 2.3 批次大小与梯度累积

- **当前**：`batch_size = 48`。
- **建议**：
  - 显存允许可试 **64**，有利于更稳的梯度估计；显存紧张可降到 **32** 并相应略提学习率（如 2.5e-4）以补偿。
  - 若想等效更大 batch（如 96）：保持 `batch_size=48`，每 2 步再 `optimizer.step()`（梯度累积 2），等效 batch 96，学习率可维持或略增。

### 2.4 模型容量（可选）

- 在显存与训练时间允许下，可尝试：
  - **d_model**：768 → **1024**，或保持 768 先优先调 lr/步数。
  - **n_layers**：12 → **16**（需同步调 `max_steps` 与 lr，避免欠拟合）。
- 若数据量或步数有限，优先**先不动模型规模**，把学习率与步数调好再考虑加大模型。

### 2.5 正则与优化器

- **weight_decay**：当前 0.01 可维持；若过拟合可提到 **0.02**；若欠拟合可试 **0.005**。
- **dropout**：0.1 可维持；过拟合可试 **0.15**。
- **grad_clip**：1.0 可维持；若出现梯度爆炸可降到 **0.5**。

### 2.6 推理阶段采样参数（不改代码时的“调参”思路）

- **temperature**：当前 1.0；若生成太散、标点乱，可试 **0.8 或 0.85**；若太死板可试 **1.1**。
- **top_k**：80 可试 **60**（更保守）或 **100**（更多样）。
- **top_p**：0.9 可试 **0.85**（更稳）或 **0.95**。
- **max_length / max_new_tokens**：可先设为 **64 或 80**，减少后半段崩坏；需要长诗再提高。

## 三、诗词“完美收尾”的方案与策略

目标：让生成在合适位置结束，形成完整句、完整首，而不是拖成长串标点或半句。

### 3.1 策略一：利用 EOS 自然结束（推荐）

- **思路**：训练数据中每条样本带 EOS，模型已学过“在句末/篇末预测 EOS”。推理时在**足够长度之后**不再压制 EOS，让模型有机会生成 EOS 并停止。
- **实现要点**（逻辑建议，不直接改你仓库代码）：
  - 当前 `suppress_eos_steps = int(max_length * 0.9)` 表示前 90% 步数内大幅压低 EOS 概率。
  - 可改为：前 **50%–70%** 步数压制 EOS，**之后恢复** EOS 正常概率（或略微提高），一旦采样到 EOS 即停止生成。
  - 在 `model.generate()` 中：若某步采样到 `eos_token_id`，则 `break` 循环并返回当前序列，实现“遇 EOS 即收尾”。

### 3.2 策略二：按体裁长度截断（格式收尾）

- **思路**：古诗词有固定句数，如四句（绝句）、八句（律诗）。按“句”切分后，只保留到完整句数，多余部分丢弃。
- **实现要点**：
  - 生成时设定 `max_new_tokens` 略大于目标体裁总字数（如绝句 28 字 + 标点，可设 40–50）。
  - 解码得到字符串后，按句号 `。` 或换行拆成句，只保留前 4 句（绝句）或前 8 句（律诗），再拼回；若最后一句不完整（没有句号），则删掉最后一句或只保留到上一个句号。
  - 这样保证输出在“格式上”是一首完整诗，避免无限拖尾。

### 3.3 策略三：句号截断 + 最小长度（简单实用）

- **思路**：生成到一定长度后，一旦遇到句号 `。` 就视为“一句结束”，再遇到下一个句号就结束整首（或再根据体裁取前 N 句）。
- **实现要点**：
  - 设定 `min_tokens`（如 20）和 `max_tokens`（如 80）。
  - 自回归生成时，在步数 ≥ `min_tokens` 之后，若当前步采样到句号 token，则可选：
    - **方案 A**：直接在此停止（适合只生成一两句续写）。
    - **方案 B**：继续生成直到出现第 2 个或第 4 个句号（对应绝句 4 句），再停止并截断。
  - 若达到 `max_tokens` 仍未遇到句号，则从**已生成序列中最后一个句号位置**截断；若无句号，则保留到 `max_tokens` 并做一次后处理（如去掉末尾不完整片段）。

### 3.4 策略四：后处理“最后一句”规范化

- **思路**：不改变生成长度，只对模型输出做后处理，使展示时“收尾”更干净。
- **实现要点**：
  - 解码后按 `。` 或 `，` 切句；若最后一段不以 `。` 结尾且长度过短（如少于 3 字），则删掉最后一段，以倒数第二段结尾为整首结尾。
  - 若最后一段以逗号结尾，可替换为句号，表示“在此收束”（仅展示层）。
  - 可结合策略二：只保留前 4 句或前 8 句，再应用上述“最后一句”规则。

### 3.5 策略五：训练/数据层面强化“收尾”

- **思路**：让模型更清楚“哪里该结束”，从数据与目标上强调结尾。
- **实现要点**：
  - **数据**：保证每条样本末尾是句号 + EOS；若有未加 EOS 的样本，预处理时补上。
  - **损失权重**（若支持）：对序列最后若干 token（如最后 5–10 个）的损失适当加大权重，使模型更关注“收尾”预测。
  - **课程/采样**：训练时一定比例只取“从开头到第一个句号”的短序列，或“从开头到 EOS”的完整句，强化“句末/EOS”的预测。

### 3.6 策略六：解码时对 EOS/句号的概率微调（进阶）

- **思路**：在生成中后期，适当提高“句号”或 EOS 的概率，使模型更容易在合适位置结束。
- **实现要点**：
  - 步数 > 0.5 * max_new_tokens 后，对句号 token 的 logits 加一个小的正偏置（如 +0.5）；或对 EOS 的 logits 加偏置。
  - 同时保留“遇到 EOS 即停止”的逻辑，这样既鼓励收尾，又不会无限拉长。

## 四、推荐组合（落地顺序）

1. **先做**：在 `generate()` 中**遇 EOS 即停止**，并适度缩短 `suppress_eos_steps`（例如从 90% 改为 60%–70%），使后半段有机会自然结束。
2. **再做**：后处理按句号截断、只保留前 4 句/8 句（策略二 + 三），保证格式完整。
3. **视情况**：降低 `temperature`、适当 `max_length`，减少长尾乱码；再考虑策略五、六做细调。

---

## 五、小结

- **超参**：优先调**学习率、warmup、max_steps** 和**学习率衰减节奏**，再视情况动 batch_size、weight_decay、dropout；推理时用 temperature、top_k、top_p、max_length 做快速体验。
- **收尾**：以 **EOS 停止 + 按句号/体裁截断** 为主，后处理规范最后一句为辅；若仍不理想，再在训练与解码概率上做“收尾”强化。
